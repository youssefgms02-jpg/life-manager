# Life Manager — offline-first + Supabase sync

التطبيق بيشتغل محليًا وبيزامن بياناتك مع Supabase لما الإنترنت يرجع.

## التحديث من داخل التطبيق

### Windows
- نسخة Windows الجديدة هي **Setup.exe** مثبتة (NSIS)، وليست portable؛ ده مطلوب لتفعيل التحديث داخل التطبيق.
- من صفحة **البيانات ← تحديث التطبيق** اضغط **التحقق من تحديث APK / EXE**.
- لو فيه إصدار أحدث، التطبيق يقدر ينزّله ثم يطلب منك إعادة التشغيل لتثبيته. لا تحذف التطبيق يدويًا.
- ملفات التحديث وملف `latest.yml` تُنشر في GitHub Releases.

### Android
- من صفحة **البيانات ← تحديث التطبيق** افحص أحدث إصدار؛ عند توفره يظهر رابط APK الخاص بالإصدار.
- Android لازم يطلب موافقتك على تثبيت APK؛ لا يمكن للتطبيق التثبيت بصمت.
- لقبول التحديث فوق النسخة الحالية، يجب أن يكون APK الجديد موقّعًا **بنفس مفتاح التوقيع** وأن يكون `versionCode` أعلى.
- إعداد أسرار التوقيع مرة واحدة مطلوب قبل إصدار APK ثابت.

### إصدار جديد
1. حدّث `version` في `package.json` وخلّي `www/version.json` مطابقًا له.
2. ادفع التغييرات إلى `main` وانتظر نجاح البناء.
3. أنشئ tag بنفس رقم الإصدار، مثل `v1.0.2`. الـ workflow يبني Windows Setup وAPK الموقّع وينشرهما كـ GitHub Release.
4. إذا كانت أسرار توقيع Android غير مضبوطة، يفشل إصدار الـ APK بدل نشر APK debug كتحديث.

## إعداد توقيع Android الثابت (مرة واحدة)

من GitHub → **Settings → Secrets and variables → Actions → New repository secret** أضف:
- `ANDROID_KEYSTORE_BASE64`: ملف keystore مشفّر Base64.
- `ANDROID_KEYSTORE_PASSWORD`: كلمة مرور keystore.
- `ANDROID_KEY_ALIAS`: اسم المفتاح.
- `ANDROID_KEY_PASSWORD`: كلمة مرور المفتاح.

لا ترفع ملف keystore أو كلمات المرور إلى المستودع. احتفظ بنسخة آمنة من ملف keystore؛ فقدانه يمنع إصدار تحديثات تقبلها النسخ الموقعة به.

## انتقال من APK debug قديم
إذا كانت النسخة المثبتة موقعة بمفتاح debug مؤقت من GitHub Actions، فلا يمكن لـ Android قبول APK موقّع بمفتاح مختلف فوقها؛ هذا قيد أمان. قبل الانتقال، نزّل نسخة JSON احتياطية وتأكد من اكتمال مزامنة Supabase. قد تتطلب هذه النقلة وحدها إزالة نسخة debug القديمة ثم تثبيت النسخة الثابتة؛ بعدها تتم التحديثات فوق النسخة الحالية بنفس المفتاح. لا تحذف النسخة القديمة قبل التأكد من النسخة الاحتياطية/المزامنة.

## المزامنة والنسخ الاحتياطي
- كل تعديل يُحفظ محليًا حتى بدون إنترنت، ثم تتم المزامنة عند رجوع الاتصال.
- سجّل الدخول على كل جهاز بنفس حساب Supabase.
- من صفحة البيانات استخدم **تنزيل نسخة احتياطية** قبل التغييرات المهمة؛ استيراد النسخة يستبدل البيانات الحالية بعد التأكيد.
- استخدم Supabase `anon public key` فقط في التطبيق، ولا تضع `service_role` key في ملفات الواجهة.

## Web
- نسخة الويب تعمل عبر Service Worker؛ استخدم زر **تحديث نسخة الويب** أو أعد فتح التطبيق مع اتصال الإنترنت.
